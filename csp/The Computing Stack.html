Start here

One idea holds it all together

In Week 2a we said computer science is not really the study of computers, the same way chemistry is not the study of beakers. It is the study of computation: how problems get solved step by step, and how we build machines to do the steps for us.

Those machines are complicated. A laptop chip has billions of parts. Nobody, not even the engineers who design it, keeps all of that in their head at once. Instead, computers are built in layers. Each layer uses the one below it without needing to know how it works inside.

Hiding the details of a lower layer so you can work with a simpler idea on top is called abstraction. You already do this every day. You steer a car without thinking about fuel injection. You text a friend without thinking about cell towers.

★ Connection

Abstraction comes up all year in CSP. When you write Circle(200, 200, 50) in CMU CS Academy, you get a circle without writing any of the code that figures out which pixels to color. Someone else built that layer so you could stand on it.

Bottom layers

Switches and gates

At the very bottom, a computer is made of transistors: microscopic switches that either let electricity through or block it. On or off. That is why computers use binary, a number system with only two digits: 1 for on and 0 for off.

One switch cannot do much. But wire a few transistors together and you get a logic gate, a tiny circuit that takes in 1s and 0s and puts out a 1 or 0 based on a rule. The three basic gates are AND, OR, and NOT. Here is the rule for AND: the output is 1 only when both inputs are 1.

Here is the surprising part: combine enough of these simple gates and you can build circuits that add numbers, compare them, and store them. Stack millions of those circuits together and you have a processor.

★ Connection

Python has the same three words: and, or, and not. Later this year you will use them to write conditions like if x > 0 and y > 0:. They follow the exact same rules as the gates.

Hardware layer

The Von Neumann architecture

In Week 2b we met the design that nearly every modern computer follows, named for mathematician John von Neumann. Its big idea is that one memory holds both the program's instructions and its data. To run a different program, you do not rewire the machine. You just load different instructions into memory.

The fetch-decode-execute cycle

The CPU does one thing over and over: fetch the next instruction from memory, decode it to work out what it means, and execute it. Here is the short assembly program from Week 2b, traced step by step. Memory starts with ABC = 2 and XYZ = 3.

Instruction fetchedDecoded asExecuted
LOAD REGD, ABCCopy a value from memory into a registerRegister D = 2
LOAD REGE, XYZCopy a value from memory into a registerRegister E = 3
ADD REGF, REGD, REGEAsk the ALU to add two registersRegister F = 5
STORE REGF, TOTALCopy a register back into memoryTOTAL = 5
HALTStopDone

Five trips around the cycle just to add 2 + 3. A modern CPU runs billions of cycles per second, which is what a speed like 3 GHz means.

Try it

Look up your own computer's hardware. On a Mac, open the Apple menu and choose About This Mac. On Windows, go to Settings → System → About. Find the name of the processor (the CPU) and how much memory (RAM) it has.

Operating system and applications

Software: system and application

Hardware is the physical stuff you can touch. Software is the programs and data that tell the hardware what to do. Week 2b split software into two kinds.

System software runs the computer itself. The biggest piece is the operating system (OS). It starts when you turn the computer on and runs until you shut it down. It decides which program gets the CPU next, hands out memory, keeps track of files, and talks to devices through small programs called drivers. Because the OS handles all of that, an app never has to deal with the raw hardware.

Application software is everything you open to get something done: a browser, a word processor, a game, Scratch. Applications ask the OS for what they need, and the OS asks the hardware.

Try it

Watch the operating system at work. On a Mac, press ⌘ Space and type Activity Monitor. On Windows, press Ctrl + Shift + Esc to open Task Manager. Count roughly how many processes are running. The OS is sharing one CPU and one memory among all of them, right now.

Crossing the gap

The language ladder

The CPU only understands machine language. People think in English, Spanish, Japanese. Human language is full of ambiguity that a computer cannot handle, so we cannot just type English and have it turned into binary. We climb down a ladder instead. Here is the same small job at each rung: add two numbers and save the total.

  1. Natural languagefor people
    ABC is 2 and XYZ is 3. Add them and save the total.
  2. Pseudocodetwo styles; no computer runs either
    Plain
    Set total to ABC plus XYZ
    AP CSP
    total ← abc + xyz

    Plain pseudocode is written however makes sense to you. AP CSP pseudocode follows set rules, like the style on the AP exam reference sheet. Its arrow means “store the value on the right in the variable on the left.”

  3. High-level languagesame idea, seven languages
    Python
    total = abc + xyz
    Ruby
    total = abc + xyz
    Java
    int total = abc + xyz;
    C++
    int total = abc + xyz;
    JavaScript
    let total = abc + xyz;
    Go
    total := abc + xyz
    Scratch
    set total ▾ to abc + xyz
  4. Assembly languageone line per machine instruction
    LOAD  REGD, ABC
LOAD  REGE, XYZ
ADD   REGF, REGD, REGE
STORE REGF, TOTAL
  5. Machine languagebinary the CPU runs
    Operation
    4 bits    		Register
    4 bits    		Last
    8 bits    		Result
    0001LOAD1101register D0000 0001address 1 (ABC)D ← 2
    0001LOAD1110register E0000 0010address 2 (XYZ)E ← 3
    0101ADD1111into register F1101 1110registers D and EF ← D + E = 5
    0010STORE1111register F0000 0000address 0 (TOTAL)TOTAL ← 5

    From a made-up teaching computer. For LOAD and STORE, the last 8 bits are one memory address. For ADD, they are two 4-bit register numbers, because adding happens inside the CPU. Real CPUs use longer, more complicated codes, but the idea is the same.

Every high-level version says the same thing, but look for the family resemblances. Python and Ruby look identical here: no type, no semicolon. Java and C++ also match each other: both make you declare that total holds an integer (int) and end the line with a semicolon. JavaScript uses let to create a new variable, and Go uses its own := symbol for the same job. Scratch replaces typing with blocks that snap together.

Notice how one line of Python turned into four lines of assembly. That is abstraction at work: high-level languages hide the hardware so you can write less, while low-level languages (assembly and machine language) give exact control but make you spell out every step. Low-level code is also written for one specific kind of CPU. High-level code can run on many.

The translators

Something has to carry your code down the ladder. There are three main kinds of translator programs.

AssemblerTurns assembly language into machine language, one instruction at a time.
CompilerTranslates a whole program ahead of time and produces a file you can run later. C and C++ work this way.
InterpreterReads your program and carries it out as it goes, without producing a separate file first. Python works this way.

Some languages mix the two. Java is compiled into an in-between code called bytecode, which then runs on the Java Virtual Machine. That is how Java earned its slogan “write once, run anywhere”: any computer with the virtual machine can run the same bytecode.

Blocks or text?

Most of you have used Scratch, and you have been writing Python in CMU CS Academy. Both are high-level languages, and both end up as the same kind of machine instructions. The difference is in how you write them. Scratch blocks only snap together in ways that make sense, so you cannot make a typo or a syntax error, and you can focus on the logic. Python's text takes more care to type correctly, but gives you more precise control and scales up to much bigger programs.

All together

What happens when you press Run

Let's follow one line of your Unit 3 code, Circle(200, 200, 50), through the whole stack.

  1. YouYou decide you want a circle in the middle of the canvas and type the line.
  2. Hardware → OS → applicationEach keypress travels from the keyboard (an input device) to the operating system, which passes it to your web browser, which passes it to CMU CS Academy.
  3. Programming languageYou press Run. Your Python is translated, piece by piece, into instructions the machine can carry out. In CMU CS Academy this happens inside your browser, which adds a translation layer of its own.
  4. Hardware: memoryThose instructions, plus your program's data (the numbers 200, 200, and 50), are placed in RAM, side by side.
  5. Hardware: CPUThe CPU runs its fetch-decode-execute cycle millions of times, running the interpreter, CMU’s graphics code, and the browser. The result is a drawing command: a circle, at this spot, this size, this color.
  6. Hardware: GPU and outputThe GPU works out which pixels fall inside the circle and colors them all at once. The operating system sends the finished image to your screen.
  7. Gates and transistorsUnderneath every one of those steps, logic gates are combining 1s and 0s, and transistors are switching on and off.

You wrote one line. Every layer below you did its job without you ever seeing it. That is the computing stack.

Looking ahead

Why are there so many languages?

By some counts, around 9,000 programming languages have been created, and 50 to 100 are in wide use today. If they all end up as machine instructions for the same kind of hardware, why not just use one? Because each language is built around a different set of trade-offs, and no language wins at everything.

Trade-offOne endThe other end
LevelClose to the hardware: fast and precise, more work (C, assembly)Far from the hardware: less code, the language handles the details (Python)
TranslationCompiled ahead of time (C, C++)Interpreted as it runs (Python)
PurposeGeneral-purpose: good at many things (Python, Java)Built for one job: statistics in R, databases in SQL
FormText-based (Python, Java)Visual blocks (Scratch)

Languages also differ in style, or paradigm. Some spell out instructions step by step (imperative). Some bundle data and actions together into objects (object-oriented). Some build programs out of functions that avoid changing shared data (functional). And some things people call languages are not programming languages at all: HTML describes the structure of a web page and CSS describes its look, but neither one runs instructions.
