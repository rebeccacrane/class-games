Trace the Internet

CSP Unit 2 · Lesson 4: Routers and Redundancy

When you load a website, your message doesn't go straight there. It hops from router to router, maybe through a dozen of them, sometimes across an ocean. Your computer has a built-in tool called traceroute that shows you every router on the way. Today you'll use it to see the real Internet's routers for yourself.

How it works: Traceroute sends test messages that are only allowed to go a certain number of hops: 1 hop, then 2, then 3, and so on. When a message runs out of hops, the router holding it sends back a reply: "I'm here, and here's my address." Each line of the output is one of those replies.

Time: about 20–30 minutes. You'll turn in: 4 screenshots and your answers.

Words to know
Router
A device that receives a message, reads its destination address, and sends it one step closer to where it's going.
Hop
One step from one router to the next.
Round-trip time
How long a message takes to get somewhere and for the reply to come back. Measured in milliseconds (ms). 1,000 ms = 1 second.
Redundancy
Having more than one path, so there's a backup if one fails.
Fault tolerant
Able to keep working even when part of the system fails.

Each numbered line is one hop. Traceroute tests every hop 3 times, so each line has room for 3 results. Each one is either a time in ms (a router replied) or a * (no reply in time).

  • Hop 1: your home router. Every message you send goes here first. Addresses starting with 192.168 are only used inside home networks. Millions of homes use this same address. Only ~2–5 ms away.
  • Hops 2–7: your Internet provider. This home uses Comcast. The router names include seattle.wa, so you can tell where they are. Engineers name their routers, so the names are often clues. Still only ~15 ms.
  • Hops 8–9: a handoff to another company. Comcast doesn't go to Japan, so in Seattle (sttlwa01) it hands the message to NTT, a company with a worldwide network. The Internet is a network of networks: companies pass messages to each other.
  • Hop 10: * * *, no reply. This router didn't answer any of the 3 tests. Many routers ignore traceroute or answer it last, because forwarding real messages is their actual job. The message still got through. How do we know? Hop 11 answered, and to get there the message had to pass through hop 10.
  • Hops 11–12: Tokyo! (tokyjp05) The time jumped from ~23 ms to over 100 ms. That jump is the message crossing the Pacific Ocean through an undersea cable, about 7,700 km.
  • Hops 13–14: the destination. The website's own network in Otemachi, a Tokyo neighborhood full of Internet equipment, then the website itself at hop 14.
Three more things to notice:
  1. Some hops show 2 or 3 different routers. Look at hops 3–7 and 12–14. Different tests took different paths! That's redundancy: the network has several routes and spreads messages across them. If one router failed, messages would take another path. That's what makes the Internet fault tolerant.
  2. Times don't always go up. Hop 11 shows 152 ms, but hop 12 shows 102 ms even though it's farther. Routers answer traceroute after their real work, so one reply can be slow. Look for the overall pattern, not single numbers. (Same with the random 84.975 ms at hop 4.)
  3. The math checks out. Light in fiber-optic cable travels about 200,000 km per second. Seattle to Tokyo and back is about 15,400 km, so the trip should take at least 77 ms. The trace shows ~100–120 ms, because cables don't run in a straight line and every router adds a little time.

On Windows, it looks a little different

Windows lists the 3 times first, then the router. It shows only one router per hop, and * * * appears as Request timed out. A Windows trace starts like this:

C:\> tracert www.wide.ad.jp

Tracing route to www.wide.ad.jp [203.178.139.57]
over a maximum of 30 hops:
  1     5 ms     2 ms     4 ms  192.168.1.1
  2    15 ms    17 ms    15 ms  100.92.122.123
  3    16 ms    17 ms    29 ms  po-72-rur502.seattle.wa.seattle.comcast.net [68.85.144.121]
  ...
 10     *        *        *     Request timed out.

Windows looks up every router's name, so it's slower. A trace can take a minute or two. Be patient!
