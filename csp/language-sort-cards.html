Pick the Right Language

A card game about trade-offs. There's no best programming language, only the best one for a particular job, team, and platform.

Setup

  • Groups of 3–4. Each group gets one language deck (pages 2–3) and one job deck (pages 4–5).
  • Printing on two colors of cardstock makes the decks easy to separate. Print at 100% / actual size with background graphics on.
  • The job cards have write-on lines. Laminate and use dry-erase markers if you want to reuse them, or have students write answers on sticky notes.
  • The decks don't match one-to-one on purpose. Some jobs have several defensible answers, and that's where the best arguments happen.

How to play (about 45 minutes)

  1. Line them up (10 min). Teams lay the language cards in a single row, from "closest to the hardware" to "closest to how humans think." They should use the code snippets and details as evidence. Compare with a neighboring team, then share the spectrum from the key.
  2. Take the job (20 min). Shuffle the job deck face down. Flip one at a time. The team picks a language card and writes one "because" sentence. Languages can be used more than once.
  3. Challenge (10 min). Each team presents one match. Any other team can challenge with a different language, but only with an argument. Then reveal the key's deciding factor.
  4. Wrap-up (5 min). Exit question: name a job where the language was chosen for a reason that had nothing to do with the language itself.

What students should walk away with

  • Low-level languages give more control and speed but are harder to write and read. High-level languages trade some speed and control for readability and faster development.
  • Often the platform, existing code, or team decides for you: Unity means C#, Roblox means Lua, an old bank system means COBOL.
  • "Fast to run" and "fast to write" are different goals. Python is a great pick when your time matters more than the computer's.
Wild card: HTML/CSS is in the language deck to start an argument. It describes structure and style but can't make decisions or repeat steps on its own. Ask the class whether it counts as programming, and what their definition says about it.
Pythonborn 1991
for n in range(3):
    print(n)
Runs by
Interpreted, line by line
Good at
Reads almost like English. Huge libraries for data, AI, and automating chores.
The catch
Slower than compiled languages. Doesn't run natively on phones or in browsers.
Found in
Data science, AI, quick scripts, CMU CS Academy
JavaScriptborn 1995
let score = 0;
score++;
document.title = score;
Runs by
Interpreted by the web browser
Good at
The one language every web browser runs. Makes pages interactive.
The catch
Quirky rules: "2" + 2 gives "22".
Found in
Nearly every website; also web servers (Node.js)
Javaborn 1995
int x = 5;
System.out.println(x);
Runs by
Compiled to bytecode, run by the Java Virtual Machine
Good at
"Write once, run anywhere." Strict rules help huge teams work together.
The catch
Wordy. Even tiny programs need a lot of setup.
Found in
Big company servers, older Android apps, Minecraft Java Edition, AP CS A
Cborn 1972
int x = 5;
printf("%d\n", x);
Runs by
Compiled to machine code
Good at
Fast and tiny. Works very close to the hardware.
The catch
You manage memory yourself. Mistakes cause crashes and security holes.
Found in
Operating systems, microwaves, thermostats, car computers
C++born 1985
int x = 5;
std::cout << x;
Runs by
Compiled to machine code
Good at
C's speed plus tools for organizing very large programs.
The catch
Enormous and complicated. Easy to make subtle mistakes.
Found in
Game engines (Unreal), web browsers, video editing software
C#born 2000
int x = 5;
Console.WriteLine(x);
Runs by
Compiled to bytecode, run by Microsoft's .NET
Good at
Clean, modern, well supported. The scripting language of Unity.
The catch
Strongest inside the Microsoft and Unity worlds.
Found in
Unity games, Windows software, business apps
Swiftborn 2014
let name = "Ada"
print("Hi, \(name)")

Compiled to machine code

Apple's modern language. Safe, fast, and built into Apple's tools.

Mostly used only on Apple devices.

iPhone, iPad, Mac, and Apple Watch apps
Kotlinborn 2011
val name = "Ada"
println("Hi, $name")
Runs by
Compiled to bytecode, like Java
Good at
Google's preferred Android language. Shorter than Java and works alongside Java code.
The catch
Mostly used for Android and Java-world projects.
Found in
Android apps
SQLborn 1974
SELECT name FROM pets
WHERE age > 3;
Runs by
Inside a database. You describe what you want, not how to get it.
Good at
Asking questions of enormous tables of data, fast.
The catch
Not general-purpose. You can't build a whole app with it.
Found in
Behind almost every app that stores data

println!("{}", x);

Compiled to machine code

Goborn 2009
x := 5
fmt.Println(x)
Runs by
Compiled into a single file
Good at
Simple, fast, and great at doing many tasks at once. Easy to deploy.
The catch
Leaves out features on purpose, so some code gets repetitive.
Found in
Cloud services and web servers
Scratchborn 2007
when green flag clickedsay Hi! for 2 seconds
Runs by
Snapping blocks together in a web browser
Good at
No syntax errors possible. Instant animations and games.
The catch
Hard to build large or professional software.
Found in
Classrooms and first-time coders, ages 8 and up
Assemblyborn 1940s
mov eax, 5
add eax, 2
Runs by
Translated almost directly into the processor's own instructions
Good at
Total control of the chip. Nothing runs faster.
The catch
Each chip family has its own. Slow to write, hard to read.
Found in
Startup code for chips, tiny devices, speed-critical pieces
PHPborn 1995
<?php
echo "Hi, visitor!";
?>
Runs by
Interpreted on a web server, which sends back finished pages
Good at
Building web pages on the server. Cheap, easy hosting everywhere.
The catch
A messy history of inconsistent design.
Found in
WordPress (a huge share of all websites), Wikipedia
Luaborn 1993
local coins = 0
coins = coins + 1
Runs by
Interpreted, usually inside another program
Good at
Tiny and easy to plug into games and apps as a scripting language.
The catch
Very small toolkit. Rarely used on its own.
Found in
Roblox (as Luau), game mods and add-ons
COBOLborn 1959
ADD 1 TO COUNTER.
DISPLAY COUNTER.
Runs by
Compiled, usually on big mainframe computers
Good at
Business record-keeping. Reads like English. Rock-solid for decades.
The catch
Few new programmers learn it.
Found in
Banks, insurance companies, government systems
HTML/CSSborn 1993/96
<h1>Hi!</h1>
h1 { color: teal; }
Runs by
Read and drawn by the web browser
Good at
HTML gives a page its structure. CSS gives it its look.
The catch
No decisions and no loops on its own.

Discussion prompts

  • Which jobs were decided by the platform, the existing code, or the team instead of the language's features? (I, J, K, P, N)
  • We use Python in class. Which jobs would it be a poor choice for, and why?
  • Compare Q and H. What does "fast" mean in each one?
