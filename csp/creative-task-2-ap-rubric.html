Creative Task 2: Make It Interactive

AP exam version (for students taking the AP exam in May) · AP Computer Science Principles · CMU CS Academy, Unit 2: Functions, Mouse Events and Conditionals

The task

Design and code an interactive program of your choice using what you learned in Units 1 and 2. When the user clicks, drags, or moves the mouse, something in your program should change. It could be a light switch that turns a scene from day to night, a dress-up or build-a-face program, a button game that keeps score, a mood meter that changes color as the mouse moves, or anything else you invent.

Your program now responds to the user. That's the big step up from Creative Task 1. The mouse is your program's input, and what changes on the canvas is its output.

This is the same task the whole class is doing, with two extra pieces that practice the AP Create Performance Task: a mini project reference (code screenshots) and a short video. The program requirements and written responses are the same for everyone. The tags on each response show which AP skill it practices.

Your Unit 2 toolbox

Use these tools plus everything from the Unit 1 toolbox. Animation (onStep), key presses, groups, loops, and lists come in later units. If you want to use something that isn't on this list, ask Mrs. Crane first.

Functions

  • Defining a function with def
  • One or more parameters
  • Calling a function with different arguments

Mouse events

  • onMousePress(mouseX, mouseY)
  • onMouseRelease, onMouseMove, onMouseDrag

Variables and properties

  • Storing a shape in a variable
  • Reading and changing properties: centerX, centerY, left, top, width, fill, opacity, visible, rotateAngle, and others
  • Custom properties, like app.score

Math

  • + - * / // % **
  • Math functions from class, such as abs, round, min, max

Conditionals

  • if, if-else, if-elif-else
  • Comparisons: == != < > <= >=
  • Shape methods: hits(x, y), contains(x, y), hitsShape(shape)

Program requirements

Check each one off before you turn in your project.

  • The program runs with no errors in the console.
  • It responds to the user through at least one mouse event (onMousePress, onMouseRelease, onMouseMove, or onMouseDrag).
  • It includes at least one function you wrote yourself (not a mouse event) that has at least one parameter. The parameter must change what the function does.
  • Your function contains an if statement (if-else or if-elif-else is even better).
  • Your program calls your function at least twice with different arguments, and the different arguments make different parts of the function run.
  • It changes at least one shape's properties after the shape is drawn (for example, its fill, position, size, or visible).
  • The code has comments that label each part of the program, plus a comment above each function you wrote that says what it does.

Plan it first

Before you start coding, fill out the Design and Development Guide:

  1. Description: What will your program do? What does the user do, and what happens when they do it?
  2. Canvas sketch: Sketch the starting screen on a 400 × 400 grid. Then sketch what it looks like after the user interacts with it.
  3. Code design: Name the function you'll write, its parameter(s), and what the if statement inside it will check. Then list which mouse event will call it.

Working with a partner? You may build the program with one partner, just like on the AP task. Each of you must write your own function and complete your own project reference, video, and written responses on your own. Put your name in a comment above the parts you wrote.

Mini project reference

On the AP task, you'll turn in screenshots of your code that you'll use to answer questions on exam day. Practice that here. Paste two screenshots into your response document:

  1. Your function: the whole function definition, including the if statement.
  2. Where it's called: the line(s) where your program calls your function.

The AP version doesn't allow comments in these screenshots, so remove the comments before you take them. Make sure the code is large enough to read.

Video

Record a screen video of your program running. It should:

  • be 1 minute or less
  • show the user giving input (clicking, dragging, or moving the mouse)
  • show the program's output changing in response
  • have no voice narration (text captions are fine)

On a Mac, press Cmd + Shift + 5. On Windows, open the Snipping Tool and choose Record. These are the same rules as the AP video.

Written responses

Answer these after your program is finished. Each one has a tag that shows which AP Create Performance Task skill it practices.

  1. Purpose and userAP: Program Design, Function & Purpose
    Who is the expected user of your program, and what is it for? Describe one way your design meets that user's needs or interests.
  2. Input and outputAP: Program Function
    What does the user do to give your program input? Name the mouse event that handles it. Describe what output the program produces in response.
  3. DevelopmentAP: Development & Iteration
    Have someone else try your program. Describe one thing you changed because of their feedback, or one difficulty you ran into and how you solved it. How is your finished program different from your original plan?
  4. Your functionAP: Procedural Abstraction
    Give the name and line numbers of the function you wrote. What does its parameter represent? Describe what the function does and how it helps your program work as a whole.
  5. Your if statementAP: Algorithm Development
    Find the if statement in your function and give its line number. What condition does it check? Describe what happens when the condition is True and what happens when it's False.
  6. Two callsAP: Errors & Testing
    Describe two calls to your function with different arguments that make different parts of the function run. For each call, give the argument(s), say which part of the function runs, and describe the result.
  7. Logic errorsAP: Errors & Testing
    Describe a small change to your code that would not cause an error message but would make your program do the wrong thing. Explain why. (Examples: changing < to >, putting the wrong value in a comparison, or calling your function with the wrong argument.)
  8. Future goals
    What would you add or change if you had more time? Which tool from a later unit (animation, key presses, loops, lists) would help?

What to turn in

Turn in on Teams: your CMU code, your video, and your response document with the two screenshots and your written responses.
