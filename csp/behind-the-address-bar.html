Behind the Address Bar

CSP Unit 2 · Lesson 6: HTTP and DNS

When you type wikipedia.org and press Enter, two things happen before you see anything:

1. DNS: "What's the IP address for wikipedia.org?"→ 2. HTTP: "GET me the page at that address"→ 3. The page shows up

Both happen in a fraction of a second, so you never see them. Today you'll use tools already on your computer to watch each one happen.

Time: about 25–30 minutes. You'll turn in: 4 screenshots and your answers.

Words to know
Domain name
An easy-to-remember name for a website, like wikipedia.org.
DNS (Domain Name System)
The system that translates domain names into IP addresses. It's a huge network of servers, so no single computer has to know every address.
Scalability
The ability of a system to keep working well as it grows. DNS lets the Internet scale to billions of devices.
HTTP (HyperText Transfer Protocol)
The protocol your browser uses to request web pages and other files from a server. HTTPS is the secure, encrypted version.
World Wide Web
The system of linked pages and files you reach with a browser using HTTP. It runs on the Internet, but it isn't the same thing as the Internet.
Certificate authority
A trusted organization that checks a website is who it says it is, so your browser knows a secure connection goes to the real site.

Step 2Ask DNS for an address

The command nslookup ("name server look up") asks DNS the same question your browser asks. Here's what it looks like when you look up wikipedia.org. Yours will look a little different, and that's fine.

% nslookup wikipedia.org
Server:		192.168.1.1
Address:	192.168.1.1#53

Non-authoritative answer:
Name:	wikipedia.org
Address: 198.35.26.96
C:\> nslookup wikipedia.org
Server:  UnKnown
Address:  192.168.1.1

Non-authoritative answer:
Name:    wikipedia.org
Addresses:  2620:0:863:ed1a::1
          198.35.26.96
  • Server: the DNS server your computer asked. It's often your home router (sound familiar? It was hop 1 in Trace the Internet), which passes the question on to bigger DNS servers. The #53 on a Mac means it used port 53, the "door" DNS always uses.
  • Non-authoritative answer: the answer came from a DNS server that remembered it from an earlier lookup, not from the server officially in charge of wikipedia.org. Remembering answers is a big part of why DNS can handle billions of lookups.
  • Name and Address: the answer! An address with 4 numbers and dots, like 198.35.26.96, is IPv4. A longer one with letters and colons, like 2620:0:863:ed1a::1, is IPv6, the newer system with way more addresses. You might see one kind or both.

Type each command, press ReturnEnter, and answer the questions. Do all three in the same window so one screenshot shows them all. Your answers save in this browser as you type.

Step 3Watch HTTP in your browser

Your browser has hidden developer tools that show every HTTP request it sends. Let's open them.

  1. Open a new tab in Chrome or Edge.
  2. Press ⌘ Command + Option + ICtrl + Shift + I (or F12). A panel opens.
  3. Click the Network tab at the top of the panel. (If you don't see it, click » to find it.)
  4. Keep the panel open, then type the address into the tab's address bar. Each row that appears is one HTTP request.
  5. To see details, click the first row (the page's name), then look at the Headers section. General at the top shows the Request Method, Status Code and Remote Address.
  1. Open a new tab in Firefox.
  2. Press ⌘ Command + Option + ECtrl + Shift + E. The Network panel opens.
  3. Keep the panel open, then type the address into the tab's address bar. Each row that appears is one HTTP request.
  4. To see details, click the first row. The Headers tab shows the method (GET), Status and the server's Address.
  1. First, turn on the developer tools: Safari menu → Settings → Advanced → check Show features for web developers.
  2. Open a new tab, then press ⌘ Command + Option + I and click the Network tab.
  3. Keep the panel open, then type the address into the tab's address bar. Each row that appears is one HTTP request.
  4. To see details, click the first row and look at Headers for the method, status and address.

Safari's panel hides some details. If you have Chrome, Edge or Firefox, using one of those is easier.

Already loaded the page before opening the panel? The rows only appear for requests made while the panel is open. Just reload the page.

Labels can be a little different in each browser. If you can't find something, write "not shown" and keep going.
